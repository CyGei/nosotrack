# Responsive audit

The decks use the native viewport with responsive compositions and CSS scroll
snap. Header/footer stay outside the content fitting transform. No viewer toolbar
or fixed-size iframe scaling is used. See `public/deck-template/README.md` for the
layout and authoring contract.

Run `npm run audit:responsive` against a local server. The audit checks six routes
at 320×568, 390×844, 844×390, 768×1024, 1024×768, 1366×600, and 1920×1080.
For every deck it checks every slide's height/content containment at every size,
then exercises Arrow Down, Space, Arrow Up, and fullscreen. Browser script errors
fail the audit as well.

The layout audit uses reduced motion to measure settled content. Run
`npm run audit:animations` separately with motion enabled: it checks slide 2's
curve, slide 3's bars and counters, and slide 4's donut on entry and re-entry,
plus the transmission tree and evidence puzzle, at phone, tablet, and desktop
sizes. These animations follow the active slide; an offscreen slide touching
the viewport boundary must not start playback.

Playwright is a developer tool, not a runtime dependency. Set `PLAYWRIGHT_MODULE`
to its installed module path when supplied externally. `AUDIT_URL` defaults to
`http://localhost:3000`; `BROWSER_CHANNEL` defaults to `msedge`.

These are browser viewport simulations, not physical mobile-device tests.
PDF exports are separate deliverables and are not regenerated by this audit.

Browser standards: [CSS scroll snap](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll_snap/Basic_concepts)
and [scroll-snap-stop](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-stop).
